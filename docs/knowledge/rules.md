# 10 золотых правил вайбкодинга

Эта секция -- для тебя, человек. Не для ИИ. ИИ и так знает как работать. А вот ты -- можешь наступить на грабли, на которые наступают все новички.

---

## Правило 1: Новый чат -- это не потеря. Это перезагрузка

У ИИ есть лимит памяти (память одного разговора). Чем дольше диалог -- тем хуже ИИ помнит начало. Через 50-100 сообщений он начинает тупить, путать, забывать что ты просил.

**Что делать:** закончил задачу -- начни новый чат. Не бойся. Если проект правильно настроен (см. правило 2), ИИ подхватит контекст за секунды.

**Аналогия:** это как смены на работе. Новый сотрудник приходит, читает журнал смены, продолжает работу. Не нужно каждый раз пересказывать всю историю компании.

- Неправильно: тянуть один чат часами, пока ИИ не начнёт нести чушь
- Правильно: одна задача = один чат. Закончил -- новый.

## Правило 2: Проект живёт в файлах, не в чате

Чат -- это разговор. Он закончится и исчезнет. Всё важное должно быть в файлах проекта:

- **CLAUDE.md** -- конституция проекта. ИИ читает его при каждом запуске. Сюда: описание проекта, стек, решения, правила, что делать и чего не делать
- **docs/roadmap.md** -- куда идём, что в планах
- **docs/decisions.md** -- почему приняли решение X (через месяц забудешь)
- **CHANGELOG.md** -- что изменилось и когда

Если ИИ сделал что-то важное в чате -- попроси его записать это в файлы проекта. Иначе в следующем чате он об этом не узнает.

**Аналогия:** представь что ты нанимаешь фрилансера на день. Ты же не будешь рассказывать ему весь проект голосом? Ты дашь ему документацию. CLAUDE.md -- это и есть документация для ИИ-фрилансера.

## Правило 3: Git -- это твои сейвы. Без них ты голый

Git -- система версий. Как "сохраниться" в игре перед боссом. Если ИИ сломает проект -- откатишься к рабочей версии за секунду.

**Что делать:**

- В начале проекта: попроси ИИ инициализировать Git
- Перед большими изменениями: "сделай коммит перед тем как менять"
- Сломалось всё: "откати к последнему рабочему коммиту"

GitHub -- это облачное хранилище для Git. Проект не потеряется даже если ноутбук утонет.

- Неправильно: работать без Git и молиться что ничего не сломается
- Правильно: коммит перед каждым крупным изменением

## Правило 4: Сначала план, потом код

Главная ошибка: "напиши мне приложение". ИИ радостно напишет -- криво, сложно, не то что нужно.

**Что делать:** сначала попроси план. Обсуди его. Поправь. И только потом -- "делай".

В Claude Code есть Plan Mode -- режим где ИИ только планирует, не пишет код. Используй его.

- Неправильно: "Сделай мне CRM-систему"
- Правильно: "Составь план: что нужно для простой CRM. Какие страницы, какая база данных, какие функции. Покажи план -- я скажу что убрать и добавить"

## Правило 5: Маленькие шаги, частые проверки

Не пытайся сделать всё за один запрос. ИИ теряет фокус на больших задачах.

**Что делать:** разбивай на шаги. Сделал шаг -- проверил -- следующий.

- Неправильно: "Сделай сайт с авторизацией, личным кабинетом, оплатой и админкой"
- Правильно: "Сделай страницу входа. Покажи результат" --> "Теперь добавь личный кабинет" --> "Теперь оплату"

## Правило 6: Говори "максимально просто"

ИИ обожает усложнять. Напишет "энтерпрайз-архитектуру" для TODO-списка. Это сжигает твои токены и создаёт код который невозможно поддерживать.

**Что делать:** добавляй в запросы: "делай максимально просто", "без лишнего", "для одного пользователя".

## Правило 7: Ошибки -- это нормально. Не лезь чинить руками

ИИ сломал что-то? Не лезь в код сам (ты же вайбкодер, не программист). Скопируй ошибку из терминала (чёрного окна с командами), отдай ИИ: "ты накосячил, исправь".

В 90% случаев он разберётся. В 10% -- начни новый чат (правило 1) и объясни проблему с чистого листа.

## Правило 8: Не доверяй -- проверяй

ИИ скажет "всё готово, работает идеально" с такой уверенностью, что ты поверишь. Не верь.

- Попроси проверить свою работу (консилиум)
- Протестируй сам -- открой, покликай, сломай
- Если ИИ говорит "я проверил" -- он соврал. Он не умеет объективно проверять свою работу. Это как спрашивать повара "вкусно ли он готовит"

## Правило 9: Скиллы и MCP -- не сразу

Новички бросаются устанавливать 20 скиллов и 10 MCP-серверов (способов дать ИИ руки — подключить к сервисам). Не надо. Начни с базы:

1. Научись общаться с ИИ (промпты, план, итерации)
2. Настрой Git и CLAUDE.md
3. Сделай первый проект
4. И только потом -- расширяй возможности скиллами и MCP (подключениями к сервисам)

## Правило 10: Ты -- дирижёр, не скрипач

Вайбкодинг -- это не "ИИ всё сделает за меня". Это ты решаешь ЧТО строить, ЗАЧЕМ, и КУДА идти. ИИ -- исполнитель. Очень быстрый, но без твоего вкуса, опыта и понимания задачи.

Чем лучше ты объясняешь "что" и "зачем" -- тем лучше результат. Это навык коммуникации, не программирования.
