# 🏥 Eugene Vestel: 21 репо за год за $2 800. И честный антикейс

> Один разработчик. Год с Claude Code. 21 репозиторий, 1000+ коммитов, 3 задеплоенные платформы. Итог: ноль пользователей. И это — самый ценный урок из кейса.

## Задача

Было:
- Eugene Vestel — FHIR-разработчик (FHIR — стандарт обмена медданными)
- Команды нет, только он сам
- Идея: построить несколько платформ в здравоохранении

Хотелось:
- Проверить: можно ли в одиночку с ИИ делать то, что делают команды
- Закрыть реальные дыры в медицинских данных

## Решение

Год с Claude Code. Три основных проекта:

- **AgentInterOp** — мульти-агентная система для обмена медданными между учреждениями
- **SmartHealthConnect** — платформа на SMART on FHIR (протокол для медприложений)
- **HealthClawGuardrails** — система защиты (guardrails) для ИИ в медицине

Рабочий процесс:

- Claude Code как основной инструмент
- Постоянные итерации: идея → промпт → код → деплой
- Всё на OSS (open-source), 21 публичный репозиторий

## Результат

Числа впечатляют:

- **21 репозиторий** за год
- **1 000+ коммитов**
- **3 задеплоенные платформы**
- **$2 800** всех затрат за год (Claude Code + инфра)

Теперь антикейс — и это главная часть статьи:

> «Ни один проект не обрёл пользователей, потому что ни один не решает проблему end-to-end.»

Автор честно признаёт: техника работает, код есть, платформы задеплоены. **Пользователей — ноль**.

## Подводные камни

Вывод автора (дословно переработано):

- **Вайб-кодинг даёт скорость, но не заменяет продуктовое мышление**
- ИИ отлично пишет код, но не понимает, кому этот код нужен
- Построить 21 платформу за год — можно. Сделать 1 нужную — сложнее
- Без понимания пользователя, дистрибуции, боли — получается музей кода

Урок: **техника ≠ продукт**. ИИ ускоряет исполнение, но не заменяет этап «а зачем это вообще кому-то».

Автор не жалеет — это был эксперимент. Но предупреждает: если ты думаешь «сейчас с Claude запилю стартап за месяц» — остановись и сначала проверь, нужен ли продукт вообще хоть одному живому человеку.
