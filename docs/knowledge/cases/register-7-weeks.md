# 📰 The Register: RSS-продукт за $40 и 7 недель

> Журналист без серьёзного бэкграунда в разработке собрал коммерческий продукт за 7 недель. 337 коммитов. $40 на подписку. И написал про это честный разбор.

## Задача

Было:
- Автор — журналист The Register, не senior-разработчик
- Идея: коммерческий RSS-продукт (RSScal — календарь из RSS-фидов)
- Ограничение: бюджет минимальный, команды нет

Хотелось:
- Проверить на себе: можно ли собрать реальный продукт с ИИ
- Без маркетинговых басен — написать как есть

## Решение

7 недель с Claude. Сам писал, сам деплоил.

Стек:

- **Docker** (программа-контейнер для упаковки приложений)
- **FastAPI** (Python-фреймворк для бэкенда)
- **Redis** (быстрое хранилище в памяти)
- **PostgreSQL** (основная база данных)
- **SvelteKit** (фронтенд)

Процесс:

- 337 коммитов за 7 недель (в среднем ~7 коммитов в день)
- $40 на подписку Claude (или эквивалент ~$200 в API-токенах при другом тарифе)
- Постоянный цикл: пишу промпт → Claude выдаёт код → проверяю → правлю

## Результат

- **Работающий продукт RSScal** — задеплоен, доступен пользователям
- **$40** на всё про всё (подписка Claude)
- **7 недель** от идеи до прода
- Статья в The Register — один из самых честных публичных отчётов про вайб-кодинг

Цитата автора:

> «Вайб-кодинг работает. Хотел бы я, чтобы это было не так.»

Фраза неслучайная — автор изначально был скептиком.

## Подводные камни

Автор специально писал не хвалебную статью. Что заметил:

- Claude часто «уверенно» пишет неправильный код — нужно проверять всё
- На старте много времени уходит на понимание, как правильно «разговаривать» с ИИ
- Без базового понимания архитектуры получится каша — Claude не мыслит продуктом, он мыслит задачей
- Дебаг сложнее: свой код ты понимаешь, сгенерированный — сначала разбираешь

Но итог всё равно: продукт есть, работает, затраты смешные.
