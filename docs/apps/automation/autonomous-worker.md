# Autonomous worker

!!! info "🤖 Что это"
    Это рабочая схема для автономного исполнения задач: не просто оркестрация, а полный цикл с проверками и обновлением статуса.

## Задача слоя

Этот слой нужен, чтобы проект мог:

- брать задачу из очереди
- создавать изолированное рабочее пространство
- запускать агента на выполнение
- прогонять проверки
- либо исправлять ошибки, либо завершать задачу
- обновлять статус обратно в трекер

## Общий цикл

```text
ticket → workspace → agent → checks → fix loop → status update
```

## Компоненты

### 1) Ticket source

Источник задач может быть разным:

- Linear
- GitHub Issues
- внутренний backlog
- ручная очередь

Важно не источник, а то, что задача имеет:

- ID
- заголовок
- описание
- приоритет
- критерии готовности

### 2) Workspace

Для каждой задачи создаётся отдельная изолированная папка или ветка.

Зачем это нужно:

- меньше конфликтов
- проще откатить неудачную попытку
- легко хранить логи и артефакты
- можно параллелить задачи

### 3) Agent

Исполнитель делает конкретную работу:

- пишет код
- правит документы
- собирает тесты
- формирует результат

Агент не должен сам считать себя завершённым только потому, что он что-то сгенерировал.

### 4) Checks

Перед завершением нужны проверки:

- lint
- typecheck
- unit tests
- build
- smoke check
- при необходимости AI review

### 5) Fix loop

Если checks упали:

- логи возвращаются агенту
- он вносит правки
- проверка запускается снова

Это ключевая часть автономности.

### 6) Status update

Когда всё прошло:

- статус меняется на `Done`
- в трекере остаётся понятный след
- в логах есть, что делалось и почему это принято

## Правила слоя

- не доверять агенту финальный статус без проверок
- не смешивать оркестрацию и контроль качества
- не держать рабочее состояние только в чате
- всегда иметь лог и артефакты
- сначала проверка, потом Done

## Минимальные статусы

- `queued`
- `assigned`
- `in_progress`
- `blocked`
- `fixing`
- `ready_for_check`
- `done`
- `failed`
